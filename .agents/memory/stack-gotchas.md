---
name: Stack gotchas (Orval codegen, Tailwind v4, SSE marker lines)
description: Non-obvious failures in the monorepo's OpenAPI codegen, Tailwind v4 theming, and SSE streaming of LLM replies with trailing marker lines
---
- Orval emits a colliding `<OperationId>Params` type when a single operation declares BOTH path and query params, and the generated client fails tsc. **Why:** hit while generating the api client for a new feature. **How to apply:** keep api-spec operations path-param-only (split filtered variants into separate paths) or rename operationIds until generated type names are unique.
- Tailwind v4 `@theme inline` tokens create utilities (e.g. `bg-surface`) but do NOT emit raw `var(--color-*)` custom properties. Styles that reference `var(--color-x)` directly resolve empty (white-on-white cards). **Why:** mockup CSS ported from the canvas sandbox silently broke this way. **How to apply:** when porting mockup styles into an artifact, audit raw `var()` references and define those custom properties in an explicit `:root` block next to the `@theme`.
- When an LLM reply streams over SSE and ends with a machine-readable marker line (e.g. `OPTIONS: [...]` → tap chips), holding back only the *unterminated* tail leaks the marker whenever the model terminates it with a newline — which it often does. **Why:** code review caught raw marker JSON reaching users and the DB in the first implementation. **How to apply:** withhold the last *non-empty* line (plus trailing whitespace) until more text follows it or the stream ends; on finish, parse the held line for the marker; additionally strip ALL trailing marker lines from the persisted text (double-marker misbehavior). Keep the filter a pure function so it's unit-testable off the server.
- The Tailwind v4 `@theme inline` trap is now structurally unreachable in next-leap rather than worked around: `:root` owns raw un-prefixed literals (always emitted, so `var()` from inline styles and SVG `fill`/`stroke` always resolves), `@theme inline` owns only `--color-*` → `var(--raw)` mappings (so opacity modifiers like `bg-card/60` still work), plain `@theme` owns type/radius/shadow (which DOES emit real custom properties). `check:tokens --strict` fails the build if `:root` declares a `--color-*` or any `.tsx` references `var(--color-…)`. **Why:** the old workaround re-declared four values by hand and `shadow-[var(--shadow-sm)]` was silently rendering no shadow at all.
- `env(safe-area-inset-*)` is always `0` until the viewport meta carries `viewport-fit=cover` — so a lone `env()` usage can look correct and be a no-op for months. Adding the meta *creates* the inset problem on every bottom-fixed surface at once, so the meta change and the padding fixes must land together. Corollary: `env(x, fallback)` does not help you test it, because the fallback only fires when the feature is unsupported, not when the value is zero — headless Chromium reports real zeros. Screenshot harnesses need a separate `--sai-*` var in the `max()`.
- Removing `maximum-scale=1` from the viewport (correct — it disables pinch-zoom) makes iOS zoom on focus for any input under 16px. Every focusable input has to reach 16px in the same commit or the fix reads as a regression.
- Google Fonts is unreachable from the browser in the Replit agent container (`ERR_CONNECTION_RESET`) even though `curl` fetches it fine through the proxy. `document.fonts.check()` returns **true** for an unloaded family because it answers "would this render", so it is useless as a probe — enumerate `document.fonts` instead. next-leap now self-hosts (`pnpm run fonts`), which also removes two render-blocking third-party requests and lets the service worker serve type offline.
- `ChoiceChips`-style components that build `className` with a template string cannot be overridden by callers: `flex-wrap` and a caller's `flex-nowrap` both survive and stylesheet order decides. Use `cn()` (tailwind-merge) wherever a component accepts `className`.
